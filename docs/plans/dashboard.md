# 대시보드 — 계획과 기록

> 2026-09-12 · 사용자 제공 Figma 시안(Analytics Dashboard, community)의 양식을 유지하면서 이 프로젝트의 결과와 계산기를 담는다.

## 요구사항 (사용자)

1. 시안의 양식을 유지한다 — 좌측 사이드바, 우측 카드 격자, 흰 카드에 둥근 모서리와 옅은 그림자, 파란 강조색.
2. **부드러운 스크롤로 내려가는 한 페이지**여야 한다.
3. 스크롤이 다음 구역에 닿으면 **사이드바의 활성 항목이 자동으로 바뀐다.**
4. 사이드바 항목을 누르면 해당 구역으로 **빠르고 부드럽게 스크롤**한다.
5. 적용 대상은 **결과 대시보드와 계산기 둘 다**다.

## 기술 판단

Streamlit으로는 3·4번(스크롤 위치에 따른 사이드바 전환, 앵커 스크롤)을 만들 수 없고 시안의 레이아웃도 재현되지 않는다. 그래서 **HTML·CSS·JS 한 페이지**로 만든다. 계산기는 이 페이지의 마지막 구역에 넣는다 — 계산식이 단순해(EV = (순마진 비중 × η_I − 시간당 비용) × Ē) 브라우저에서 그대로 계산된다.

기존 Streamlit 앱(`app/calculator_app.py`)은 같은 계산을 하는 두 번째 구현이 된다. 대시보드가 자리를 잡으면 정리 여부를 사용자에게 확인한다.

## 구조

| 파일 | 책임 |
|---|---|
| `app/dashboard/template.html` | 마크업. 데이터는 `__DATA__` 자리에 주입된다 |
| `app/dashboard/styles.css` | 시안의 색·간격·카드 스타일 |
| `app/dashboard/dashboard.js` | 스크롤 감시(사이드바 자동 전환), 앵커 스크롤, 계산기 재계산, 표·막대 렌더링 |
| `analysis/dashboard.py` | 산출물 CSV → 대시보드 데이터(JSON) 구성. 순수 함수라 테스트한다 |
| `analysis/22_build_dashboard.py` | 빌드 — `outputs/dashboard/`에 index.html·정적 파일·data.js를 만든다 |
| `tests/test_dashboard.py` | 데이터 구성 함수 테스트 |

차트 PNG는 `outputs/charts/`를 상대 경로로 참조한다(복사하지 않는다).

| **계산기** | 시간당 비용·순마진 비중 입력 → 세그먼트 부호·필요 순마진 비중·배분 비교 재계산 |

## 판정 규칙 (착수 전 고정)

1. 수치는 전부 `outputs/`에서 읽는다. HTML에 손으로 적지 않는다.
2. 시안의 더미 값(사용자 이름, 학습 진도 등)은 쓰지 않는다. 양식만 가져온다.
3. 한계 표시는 대시보드에도 남긴다 — 가상 배분, 관측 연관, 상한.
4. 외부 CDN·폰트를 불러오지 않는다. 인터넷 없이 열려야 한다.
5. 계산 결과는 Streamlit 계산기와 같은 값이어야 한다(같은 정의, 같은 입력 → 같은 부호와 배분 수치).
