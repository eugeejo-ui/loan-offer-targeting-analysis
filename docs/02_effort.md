# Phase 2 — 공수 측정

> 2026-09-11 · 진행계획·기록 [`plans/phase-02-effort.md`](plans/phase-02-effort.md) · 스크립트 `analysis/07~08` · 테스트 29 passed · 모집단 29,131건

## 요약

- 공수는 **직원이 업무 항목을 실제로 작업한 시간**으로 잰다. 성사 케이스 한 건에 드는 공수의 중앙값은 약 0.56시간이다.
- 작업 구간은 대부분 몇 분이지만, 소수의 긴 구간이 합계를 크게 부풀린다. **활동별 p99 캡**을 주 지표로 쓴다.
- 캡을 어떻게 잡아도 케이스 순위는 거의 같다(순위 상관 0.996 이상). 반면 **직원 이벤트 수로 재면 순위가 꽤 달라진다**(0.707). 그래서 Phase 5에서는 이벤트 수 기반 공수를 민감도 분석용으로 함께 쓴다.
- 취소 케이스는 전체 공수의 17.8%, 거절 케이스는 16.4%를 쓴다. **케이스당 공수는 거절이 가장 크다.**

## 1. 측정 정의

- **작업 구간:** W_ 업무 항목의 start 또는 resume에서 같은 항목의 다음 이벤트까지. 공수는 이 구간 시간의 합이다.
- **넣지 않는 것:** 멈춘 상태(suspend)의 대기 시간, Phase 1에서 고객 보유로 분류된 구간.
- **시스템 계정:** 작업 구간 238,131개 중 User_1이 시작한 구간은 0.0%다 (`07_active_segments.py` 출력). 시간 지표에서는 따로 제외할 필요가 없다.
- **구간을 끝내는 이벤트:** suspend 198,345 / complete 38,812 / start 974. ate_abort·withdraw로 끝나는 구간은 없다 (`07_active_segments.py` 출력). 중단은 항상 멈춘 상태에서 일어나므로, 중단된 업무의 작업시간도 그대로 공수다.

## 4. 견고성 — 캡 방식과 이벤트 수에 따른 순위 상관

케이스 수준 Spearman 순위 상관 (`outputs/p2_effort_rank_corr.csv`):

| | 캡 없음 | p99 캡 (주 지표) | 1시간 캡 | 4시간 캡 | 직원 이벤트 수 |
|---|---|---|---|---|---|
| p99 캡 (주 지표) | 0.996 | 1.000 | 0.998 | 0.996 | 0.707 |

- **캡 방식은 결론에 영향을 주지 않는다.** 시간 기반 지표끼리의 순위 상관은 모두 0.996 이상이다. 캡 대안은 Phase 5에 넘기지 않는다.
- **시간과 이벤트 수는 다른 것을 잰다.** 이벤트 수에는 멈춤·재개가 반복될 때마다 늘어나는 기록과 작업시간이 없는 A_·O_ 이벤트가 섞인다 (P5). 순위 상관이 판정 기준 0.9에 못 미치므로, Phase 5는 이벤트 수 기반 공수를 **민감도 분석용**으로 함께 계산한다.

## 6. 다음 Phase로 넘기는 것

- **Phase 5:** `outputs/p2_case_effort.parquet`의 `effort_hours`(p99 캡)를 케이스 공수 E로 쓴다. 민감도 분석용 대안은 `staff_events` 하나다. 공수 규모가 케이스당 1시간 안팎이므로, η의 단위(공수 1시간당 기대 대출금액)가 크게 나온다는 점을 Phase 3에서 정의에 반영한다.
- **Phase 7:** 결과별 공수 비중(취소 17.8%, 거절 16.4%)과 케이스당 평균(거절 0.854시간)이 출발값이다. 취소는 Phase 1의 자동·수동 구분으로 다시 나눈다.
